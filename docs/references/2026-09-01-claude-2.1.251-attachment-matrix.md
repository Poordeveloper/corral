# Claude Code conversation attachment, measured first-party

> Compatibility evidence for the task that closes Claude's native-resume
> bypass (ADR 0011; plan design 8). Every claim below is from a run performed
> for this record on this machine, not from `--help` alone and not from the
> PR5 matrix. It is evidence about **this version**, and it sits beside
> `docs/references/2026-08-27-pr5-claude-code-hook-matrix.md` in
> `PRODUCT.md` §10's row for this provider.
>
> What it has to establish is narrower than a hook matrix and sharper: which
> arguments join a conversation that already exists, and — because ADR 0010 D2
> requires a refusal to read the command line the way the provider's own parser
> reads it — every spelling each of them has.

## Method

| | |
|---|---|
| Claude Code | **2.1.251**, installed at `~/.claude/local/claude` (local install, self-updating channel) |
| OS | macOS, Darwin 25.5.0, arm64 |
| Corral commit | `e9caee3` (branch `task/pr6-followup-claude-attachment`, before the implementation landed) |
| Date | 2026-09-01 |

Probes that only needed a parse ran with standard input closed, where this CLI
falls into print mode and answers before touching a conversation. Probes that
needed the interactive path ran in a tmux pane, in a directory this machine had
already trusted, and were quit at the prompt — no scenario submitted a prompt,
so none of this consumed model output.

## Scenarios

### 1. The inventory — what attaches at all

From `--help` on this version, then each driven below:

```text
-r, --resume [value]   Resume a conversation by session ID …
-c, --continue         Continue the most recent conversation …
    --from-pr [value]  Resume a session linked to a PR …
    --cloud [description|session_id|url]
                       … or open an existing one by session ID or URL
    attach <id>        Open a background session in this terminal
```

`--fork-session` is documented as working "only with `--resume` or
`--continue`" and is scenario 5.

### 2. `--resume` attaches, and takes four spellings — **pass**

```text
claude --resume <uuid>     → No conversation found with session ID: <uuid>
claude --resume=<uuid>     → No conversation found with session ID: <uuid>
claude -r<uuid>            → No conversation found with session ID: <uuid>
claude -r=<uuid>           → Error: --resume requires a valid session ID … Provided
                             value "=<uuid>" is not a UUID …
```

All four reach the resume path. The fourth is the interesting one: commander
does **not** strip `=` from a short flag's attached value, so `-r=<uuid>` is a
resume with a malformed id rather than a resume with a clean one — still an
attachment attempt, and still refused.

A bare `--resume` or `-r` with no value opens the picker, which is a list of
conversations that already exist.

### 3. Short flags cluster, and `-c` hides inside one — **pass**

```text
claude -pc   → Error: No deferred tool marker found in the resumed session …
```

`-p` is print and `-c` is continue; the error is `--continue`'s, so the cluster
was expanded and the conversation was joined. A refusal that only knew the word
`-c` would miss this.

### 4. A value-taking letter ends the cluster — **pass**

```text
claude -nc   → Error: Input must be provided … when using --print   (no continue)
claude -dc   → Error: Input must be provided … when using --print   (no continue)
claude -wc   → Error: Can only use --worktree in a git repository … (no continue)
```

`-n <name>`, `-d [filter]`, and `-w [name]` take the rest of the cluster as
their value, so the `c` after them is a value and not a request. Contrast
scenario 3, where the same letter after `-p` did continue. This is why the
scan stops at `n`, `d`, `w`, and `r` rather than reading every letter.

### 5. `--fork-session` alone attaches nothing — **pass**

Driven interactively: a fresh session opened at an empty composer, with no
picker and no restored conversation. It is not refused, and this is the
measurement that says so rather than the help text.

### 6. `--from-pr` attaches — **pass**

Driven interactively with a PR number that has no session
(`claude --from-pr 999999`): the conversation **picker** opened, headed "No
conversations found in this project". It resolves to existing conversations
even when the PR names none, so it is refused.

### 7. `attach` is a subcommand, and only as the first argument — **pass**

```text
claude attach foo      → No job matching 'foo'. Run 'claude agents' to list …
claude -p attach foo   → the words reached the model as a prompt
```

Commander dispatches a subcommand only in first position. So `attach` is
refused there and is ordinary text anywhere else.

### 8. `--` ends option parsing — **pass**

```text
claude -- --resume <uuid>  → "`--resume` is a CLI flag, not a prompt — it looks like
                              it landed in the chat instead of your shell. Nothing to
                              resume here; this session started fresh."
```

The provider says it in its own words: after the separator a flag-looking word
is prompt text. Nothing after it is refused, and Corral's own injection sits
ahead of every caller word where nothing there can reach it.

### 9. A required option value swallows the next word, separator included — **pass**

The scenario that made a value table necessary after all. Commander is greedy
for a required value where clap is not, so the word after such an option is not
an argument at all — and when that word is `--`, everything behind it goes back
to being options.

```text
claude -p --name x            → Error: Input must be provided …        (no continue)
claude -p --name -- --continue → Error: No deferred tool marker found in the
                                 resumed session …                     (CONTINUED)
claude -p -n -c               → Error: Input must be provided …        (-c was the name)
claude -p -pn -c              → Error: Input must be provided …        (cluster ending
                                 in n swallowed -c)
claude -p -np -c              → Error: No deferred tool marker …       (n took "p";
                                 -c stayed a flag)
```

The second line is the bypass: `--name` ate the separator and `--continue`
parsed normally. A scan that stopped at that `--` would let through exactly
what this refusal exists to stop, and the same shape hides a later
`--settings` from the first ground. The third is the mirror image — reading a
swallowed `-c` as a request refuses somebody's session name.

**Optional values are not greedy, measured both ways:**

```text
claude -p -d -c                  → Error: No deferred tool marker …   (-d did not eat -c)
claude -p --debug -- --continue  → a model answer about having nothing to continue,
                                   not --continue's own error         (separator stood)
claude -p -- --continue          → the same shape of model answer     (control)
```

So the refusal skips a word only after a **required**-value option. Listing an
optional one would skip a word that is really a flag, which is the same bypass
from the other side.

**Clap is not commander, and Codex is unaffected:**

```text
codex -C -- resume --last  → error: a value is required for '--cd <DIR>' but none
                             was supplied
```

Clap refuses to take the separator as a value rather than swallowing it, which
is why the Codex adapter's "values run until a word that opens with a dash"
model is right there and wrong here. Two providers, two parsers, two readings —
which is what ADR 0010 D2 asks for.

### 10. `--help` is not this CLI's inventory — **measured**

The scenario that invalidated this document's own method. Claude's help omits
options the root parser accepts, so a refusal list derived from it has holes at
exactly the names nobody thinks to check.

**Method.** `strings` over the installed binary yields candidate option
declarations and standalone `--flag` tokens; each candidate is then classified
by asking the root parser itself, with standard input closed so nothing reaches
a model:

```text
claude -p <flag>
  → error: option '<flag> <value>' argument missing   a root option, value required
  → error: unknown option '<flag>'                    not a root option
  → anything else                                      a root option taking no value
```

**Result on 2.1.251:** 69 root options require a value, and **40 of them never
appear in `--help`**. Eight further root options are hidden and take none.
Among the hidden set:

```text
claude -p --remote                        → Error: --cloud cannot be combined with --print.
claude -p --append-subagent-system-prompt → error: option '--append-subagent-system-prompt
                                            <prompt>' argument missing
```

`--remote` names itself `--cloud` when refused: a deprecated alias for an
attaching flag, invisible to the help, and unrefused until now.

**The bypass, still live at `bb33137`:**

```text
claude -p --append-subagent-system-prompt -- --continue
  → Error: No deferred tool marker found in the resumed session …
```

Same separator-swallow as `--name`, through a required-value flag the help does
not list. A typed one fails loudly instead — `--max-turns -- --continue` answers
`argument '--' is invalid. must be a number` — so the silent case is the
free-text options.

**What changed because of it.** The tables are now measured rather than read
off `--help`, and — more to the point — a flag in neither table is *unknown*
rather than assumed harmless: the word after it is still judged, and a `--`
after it is not trusted to end the options. Completeness now buys precision,
not safety.

## Limits

- **`--cloud` was not driven, deliberately.** Opening or creating a cloud
  session is a real side effect on an account, and a probe that "just checks"
  would be a probe that created something. It is refused on its documented
  behaviour — one flag that either creates or opens by session ID or URL — plus
  ADR 0011 D2's tie-break for an argument whose meaning the provider chooses
  from a value at runtime. That makes it the weakest entry in the refusal list
  and the one to revisit first if a person reports being refused a creation.
- The tables are measured against this build and will age. Scenario 10's design
  is what keeps that from being dangerous: a flag in neither table is read
  conservatively, so a new release costs a refused prompt rather than a missed
  attachment. Re-deriving them is still the first thing to do against a new
  version.
- **The attachment list is a denylist, and a denylist over a surface whose
  inventory the help does not expose cannot be proven complete.** Six spellings
  are refused because six were found; a seventh that this build never learns of
  is a hole no algorithm here closes. The structural alternative — refusing
  every caller flag Corral does not recognise — is a policy decision, named
  here rather than taken.
- Every scenario is macOS on 2.1.251. A spelling a later release adds is one
  the refusal does not know; the degradation is the same as every other
  version-sensitive claim here — the launch proceeds and Corral learns what it
  learns.
- `--bg`, `--remote-control`, and this CLI's other seventeen subcommands were
  not driven. They are outside ADR 0011's ground and are named as open
  questions there rather than silently skipped.
- No scenario submitted a prompt, so nothing here says anything about hook
  behaviour; that remains the PR5 matrix's.
