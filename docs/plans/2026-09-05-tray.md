# Tray — the macOS watch surface: status item, attention menu, windowless watchfulness, Quit

## Status

**Accepted 2026-09-05.** Every product decision is ruled in
`docs/decisions/2026-09-05-tray-grill.md`; this plan materializes them and
decides nothing new. The mechanism is sealed: `tray-icon` 0.24.2 + `muda`
0.19.3 (D3), on the reconciliation below.

Reconciliation of Design 0 (`docs/references/2026-09-05-tray-probe.md`)
against D1–D5: the self-driven cases held — one status item, created inside
gpui's running loop (case 1); three programmatic close/reopen cycles and a
windowless phase with the poll running and `on_window_closed` reporting the
count after removal, which is the fact D1's rule needs (case 3); menu and
badge swapped as one generation on a structural change and never on an
unchanged projection, ids carrying session identity (case 5); ~82 MiB RSS
and ~1 % CPU windowless in the debug profile with the real 1 Hz poll,
recorded rather than thresholded (case 6). The human cases 2 and 4 — the
click, Open Corral, New Session…, a row click twice across a generation,
Dock reopen, Quit — were not run before D3: the founder chose to proceed on
the self-driven evidence ("直接D3"), so those actions are performed on the
feature itself in this plan's human DoD walk, which asks the same questions
of the same mechanism; a failure there stops the merge and reopens Q3
exactly as a probe failure would have. Materialization deltas, none of them
a new decision: `Established` holds the item behind `tray::StatusItem`, so
the Watch stays platform-free and its tests show a remembering item what
the real one is shown; the menu is decided as a pure value
(`TrayProjection::menu`) the platform maps mechanically; New Session… is not
offered while the daemon is unreachable, as in the window; `cx.activate`
moved into `ensure_main_window`, so every way in brings Corral forward.

Class B: a new surface inside the accepted client envelope. No wire
change, no storage, no unsafe, no runtime ownership. The new direct
dependencies require human review and merge under the dependency policy.
Escalation triggers: none. Superseded ruling: PR9 plan grill round 2 Q7
("closing the last window is quitting") now holds only without an
established tray (Q1, Q8).

## Goal

The ambient watch surface `PRODUCT.md` §7 promises: a menu-bar status item
whose badge is the daemon's unacknowledged attention count, a menu grouping
Needs You and Ready sessions with Open, New Session and Quit, a Desktop
process that stays watchful with no windows while — and only while — the
status item exists, and a Quit that warns once per attempt when
Corral-launched sessions continue. macOS only.

## Non-goals

OS notifications (their product policy is frozen in grill Q12; delivery is
a later plan after packaging supplies an `.app`). Linux tray. A menu-bar-only
Accessory app. A `corral-tray` process. Any tray-side attention derivation,
ranking, or acknowledgement. Notification preferences. Start-hidden.

## Existing owner / architecture involved

- `corral-desktop::app` — `MainWindow` owns the bridge, the 1 Hz poll, the
  `SessionList` projection, and the last-window-closed → `cx.quit()` rule.
  The window is the only selector and the only Open path.
- `corral-desktop::sessions` — `SessionList::take` (one generation at a
  time, `is_current()`, the unreachable banner), `Row`, `coarse_age`.
- `corral-desktop::bridge` — `Polled { listing, summary, capabilities }`,
  `Unanswered`, one poll in flight.
- `corral-client::presentation` — `MainState`, `present_at`, `state_line`,
  `acknowledgeable`; the words every surface uses.
- Wire (read only): `attention.summary` per-class `total` /
  `unacknowledged`; `session.list` rows with `origin` and
  `execution_state` as daemon facts and `attention.items[]`.
- gpui 0.2.2: `on_reopen`, `on_window_closed`, `set_menus` + app-level
  `on_action`, `Window::prompt`, `quit`. It implements
  `applicationWillTerminate` only, never `applicationShouldTerminate`.

## Design

### D0 — Probe (grill Q4, Q9)

`crates/corral-desktop/examples/tray_probe.rs`, disposable: a gpui app with
one window, a `tray-icon` status item with a `muda` menu, a synthetic
projection that changes every 5 s (reorder, disappearance, replacement,
same session with a changed state, old item id replaced by a new one), a
programmatic close/reopen loop of ≥3 cycles, and a sampler writing RSS /
CPU / wakeups once a second to a log while windowless, with the real 1 Hz
poll shape running. Every menu event logs its `MenuId`, thread id, and
whether it arrived inside gpui's foreground. The founder performs the
status-item click, Open Corral, New Session…, Quit Corral and Dock reopen
in an unlocked Aqua session. Result:
`docs/references/2026-09-05-tray-probe.md` — the six cases against Q9's
pass criteria, the numbers, the commit that carried the probe. The probe
is deleted when the feature lands; the reference names the commit.

### D1 — `watch::Watch`: the process beyond its windows (Q1, Q8)

A new app-level entity owns what must outlive a window: the `Bridge`, the
poll loop and `SessionList` (moved out of `MainWindow`), the `TrayPresence`,
and the Quit gate. `MainWindow` holds `Entity<Watch>`, observes it, and
keeps only presentation: the opened terminal, overlay, form, notice.
Selection stays in `SessionList` because the one main window is the only
selector; a tray row click selects through the same list.

`TrayPresence` is `Established(StatusItem)`, `Unavailable(String)` (macOS
initialization failed: reason logged), or `Unsupported` (Linux). It is
decided in `main` before the first window (Q14). Lifecycle, as one pure
rule under test: last window closed → `Established` keeps the process,
anything else quits. `Unavailable` also renders the persistent banner
"Menu bar icon unavailable — closing this window quits Corral." in the main
window; `Unsupported` renders nothing. No retry within a run.

`ensure_main_window(cx)` is the one reopen path: reuse the open window
(activate it) or open one. Tray "Open Corral", Dock `on_reopen`, and a tray
row click all go through it. A window that fails to open quits, as today:
visible and deterministic rather than a process only the tray can reach.

### D2 — `tray::TrayProjection`: a pure value of daemon truth (Q6, Q7, Q10, Q13)

Platform-independent, built from one `Polled` generation and a clock:
badge = `needs_you.unacknowledged + ready.unacknowledged`, rendered `""`
at 0, exact to 99, `99+` from 100; two groups with the daemon's `total`
for the header "Needs You N · Ready M"; rows in `session.list` order for
sessions whose presentation state is `NeedsYou` / `Ready`, capped at 10
per group with an overflow count; each row `{ session_id, item_id,
acknowledged, title, context, age_bucket }`, where `age_bucket` is
`<1m`, whole minutes to 59, whole hours to 47, then days — so a second
of clock never changes the value. Row text: a leading `•` on an
unacknowledged row, none on an acknowledged one; then title, the
presentation's state/context wording, the age. Working, Unknown, Exited
never appear. When the list is not current (`is_current()` false) the
projection is `Unreachable`: badge empty, a disabled header line from
`Unanswered::line()`, no rows — stale counts are never shown as current.
The Desktop rebuilds native objects only when this value changes.

### D3 — `tray::macos::Tray`: mechanism, generations, event bridge (Q3, Q10)

*Preferred: `tray-icon` 0.24.2 + `muda` 0.19.3; final: pending D0.* Both
resolve to the `objc2` 0.6.4 / `objc2-app-kit` 0.3.2 already in the lock;
target-scoped to macOS and with default features off, because their
defaults are the Linux GTK3/libxdo paths and would enter the lockfile — and
cargo-deny's advisory sweep of it — without ever building (Q2). The icon is a
template RGBA glyph built in code (no asset pipeline). `Tray::new` returns
`Result`; any error is `Unavailable`.

A rebuild constructs a complete new `muda::Menu` from the projection and
swaps it with `set_menu` and `set_title` as one generation. `MenuId` carries
the action itself — `open`, `new`, `quit`, `more`, `session:<CorralSessionId>`
— so a click resolves a session identity, never a position, and a click on
a superseded generation still names the right session (Q10 stale click).

The event bridge: `MenuEvent::set_event_handler` is installed once and
only sends the `MenuId` down a `futures::channel::mpsc::UnboundedSender`;
a foreground task spawned in `Application::run` awaits the receiver and
calls `Watch::act(TrayAction, cx)`. No gpui object is touched in the
handler (Q3 thread rule). `TrayAction::OpenSession(id)` →
`ensure_main_window`, `list.select(id)`, the window's existing Open path
against current truth; a session no longer listed converges to the
current list with no action. `More` → `ensure_main_window`. `Quit` → D4.

### D4 — `quit::Gate`: one gate for every Quit (Q8, Q11)

`Watch::request_quit(cx)` is the only exit: bound to ⌘Q and the window
action, to a gpui app menu "Quit Corral" (`set_menus` + app-level
`on_action`, so ⌘Q works with no window), and to the tray. Counts from the
latest generation only when it is current: R = `origin == managed ∧
execution_state == running`, U = `origin == managed ∧ execution_state ==
unknown` (`Row` gains these two daemon words; nothing is inferred). R == U
== 0 → `cx.quit()`. Otherwise `ensure_main_window`, then one
`Window::prompt(Warning, …, ["Quit", "Cancel"])` per attempt:

- R > 0, U == 0: "R sessions will continue running. Corral will stop
  watching them for attention."
- U > 0: "[R sessions are still running. ]Corral couldn't verify whether U
  other sessions it started have ended. Corral will stop watching for
  attention." — the first sentence only when R > 0.
- not current: "Corral can't reach its service, so it can't tell whether
  sessions it started are still running. Corral will stop watching for
  attention."

Quit exits the Desktop only: no runtime is signalled, corrald keeps its own
idle lifecycle. **Known gap:** Dock-menu Quit, logout and shutdown reach
AppKit's default `applicationShouldTerminate`, which gpui 0.2.2 does not
route to the application; those paths cannot show the warning without the
AppKit boundary Q8 rejected. Recorded here and in the reference.

### D5 — Platform envelope and records (Q2, Q14)

Linux: `TrayPresence::Unsupported`, unchanged quit-on-close, no banner,
no dependency; D2/D4 tests run there. Records: benchmarks §10 (mechanism,
validation status, the Dock-quit gap), `PRODUCT.md` §6 (macOS tray
validated; Linux no tray, no watchfulness claim), `ROADMAP.md` §5 (the
three evidence windows: attention inference, tray watchfulness, OS
notification fidelity — the last cannot start before bundled delivery).

## Interfaces or persistence changed

None on the wire; nothing persisted. `deny.toml` gains any licence the new
crates' subtrees bring, read at human merge.

## Failure / unknown states

Tray initialization fails → D1 `Unavailable`: banner, quit-on-close, no
retry. Daemon unreachable → D2 `Unreachable` projection, D4 uncertainty
copy; never N = 0 from stale data. Stale menu click → session identity
resolved against current truth, never another session. Menu open during a
rebuild → the open menu is a snapshot; its click still carries identity.
Daemon restart → items are rebuilt; the projection follows the next
generation. Window fails to open → quit, logged. Dock Quit → the recorded
gap. A `MenuId` this build cannot parse → ignored, logged.

## Tests

- `tray_tests.rs`: projection from real `Polled` shapes — badge sum and
  `99+`; header totals vs rows including acknowledged ones; the `•`
  marker; daemon order preserved; cap at 10 with overflow; exclusion of
  Working/Unknown/Exited; unchanged structure across a one-second clock
  step (no rebuild); a bucket change rebuilds; `Unreachable` when not
  current; `MenuId` ↔ `TrayAction` round trip, unknown id ignored.
- `quit_tests.rs`: R/U from rows (managed running, managed unknown,
  exited, discovered, history, absent origin); each copy variant;
  not-current → uncertainty.
- `watch_tests.rs`: the last-window rule per presence; `ensure_main_window`
  reuses a window (`#[gpui::test]`).
- `tests/bridge.rs` (real corrald): a projection over a live `Polled`
  agrees with the daemon's summary; a managed session launched through the
  daemon counts in R.
- Human DoD walk (macOS, after the probe): close the window, the item stays
  and counts; row click opens the session; Quit with a managed session
  running warns and Cancel keeps watching; ⌘Q with no window warns.

## Plan Size Justification

Over the ~150-line target because one invariant spans every section:
*watchfulness ⇔ tray presence*. The presence decision (D1), the projection
the item shows (D2), the mechanism that shows it (D3), and the Quit that
ends it (D4) each change what the others may claim; splitting them would
land a process that stays alive without a tray, or a tray without the
lifecycle it licenses — exactly the failure the grill named as the most
important one. The probe (D0) is the gate on D3 alone and is the only part
that can be cut and re-run on its own.
