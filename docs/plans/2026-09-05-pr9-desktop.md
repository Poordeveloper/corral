# PR9 — the GPUI Desktop: the first graphical session, attention, and control surface

## Prerequisites (grill Q9)

S6 merged (#43), Q6 merged (#46), the deny policy merged (#44), ADR 0017
accepted and its implementation merged and verified. This plan is written
against that tree and is not final before the last of them lands.

## Goal

The Desktop the spike grill's Q12 scoped: a GPUI application that shows
every session with the PR8 five-state projection, opens one into a terminal
view rendered from a client-side replica, and offers the M1 control
actions the accepted ladder allows — New Session, Open/Attach, input,
interrupt, detach, Continue in Corral with its disclosure, acknowledge.
It consumes the daemon's session, attention, and terminal truth through
`corral-client` and invents no runtime model of its own (`AGENTS.md`
§Client / daemon boundary).

## Non-goals (Q12)

No tray, no native notifications, no history/transcript browser, no
packaging or installer, no new provider capabilities. Linux rendering stays
unvalidated and says so in the support matrix; Linux compile and
platform-independent tests are in. No wire change: ADR 0017 completed what
a replica client needs.

## Existing owner / architecture involved

- `corral-client`: activation and the RPC surface every surface uses
  (`session_list`, `attention_*`, `session_new/continuation/resume`,
  `terminal_attach`, `open_terminal_channel`). Its `TerminalChannel` yields
  raw frames; the TUI decodes and applies them in `attach.rs`.
- `corral-tui`: today's reference client. `presentation.rs` maps a session
  row to the five-state label and secondary facts (`MainState`,
  `SessionPresentation`, `present_at`); `list.rs` decodes the list's
  loosely typed rows (`SessionListItem`) and polls every second;
  `launch.rs` runs the continuation disclosure. All of this is client-side
  vocabulary the Desktop needs identically.
- `scripts/check-dependency-direction` already names `corral-desktop` as a
  client-side crate that consumes `corral-protocol` and never `corral-core`.
- The ledger §8 decisions and the spike's measured shape: entity per
  terminal (`AnyView::cached`), custom Element positioned per wide cell,
  4 ms coalescing, tokio on its own thread bridged by a futures channel,
  qwertty-term-vt as the replica (grill Q3), `gpui = "=0.2.2"` (Q2).
- ADR 0017: the snapshot prefix a replica client must honour; the client
  rules it leaves to this plan — desync on a missing prefix, stale-epoch
  discard.

## Design

### D1 — Shared client vocabulary moves out of the TUI

`corral-client` gains `sessions` (the typed decoding of a session-list row
the TUI's `SessionListItem` is today, tolerant of unknown fields) and
`presentation` (`MainState`, `SessionPresentation`, `present_at`, the
short id). `corral-tui` re-exports and uses them; its behaviour and
snapshot tests are unchanged. One copy of the terminology law
(`PRODUCT.md` §8) for every surface, in the crate every surface already
depends on. The Desktop never depends on `corral-tui`.

### D2 — The crate

`crates/corral-desktop`, `#![forbid(unsafe_code)]`, workspace lints,
`publish = false`; dependencies `gpui = "=0.2.2"`, `corral-client`,
`corral-protocol`, `qwertty-term-vt`, `tokio`, `futures`, `uuid`. No
gpui-component in PR9: the list, the session view and a disclosure dialog
are a few `div`s, and the deny policy admitted gpui's tree, not another 237
crates. A binary `corral-desktop`; bundling is M1 completion.

Everything that can be tested without a window lives in plain modules:

- `replica.rs` — the terminal state machine. Consumes decoded frames in
  order: `Geometry` and `Palette` are held until their `Snapshot` and
  applied only when the stamps agree (one state point); a `Snapshot`
  without its `Geometry` under the advertised capability is a desync — the
  snapshot is not installed and a `ResyncRequest` is sent; prefix members
  and snapshots for an epoch the replica has left are discarded. The
  parser is applied inside a poison boundary: a panic destroys the replica,
  never the process; the view shows *Terminal unavailable* and one
  automatic resync is requested; if the rebuilt replica fails again in the
  same episode, automatic retry stops until a new epoch arrives or the
  person opens the session again (grill Q3's bounded loop). Input is
  encoded from the replica's own modes (DECCKM, bracketed paste); the wire
  stays dumb.
- `bridge.rs` — a tokio runtime on its own thread; per attached session a
  reader task decoding frames into a futures channel and a writer task for
  Input/Resize/ResyncRequest; activation and reconnection through
  `corral-client` with the TUI's backoff shape; hello capabilities
  recorded so `replica` knows what the daemon promised.
- `sessions.rs` — the list model: `session_list` and `attention_summary`
  polled every second as the TUI does (a push channel is a protocol
  addition and not PR9's), rows presented through `corral-client::presentation`,
  runtime truth shown beside a degraded semantic state, never the reverse.
- `actions.rs` — New Session (provider choice and arguments under ADR
  0012's grammar, the same validation the CLI applies), Open/Attach
  (`terminal_attach` then the channel), input, interrupt (the replica's
  own `^C` bytes), detach (close the channel; the run lives on), Continue
  in Corral (`session_continuation` preflight, the disclosure rendered
  before `session_resume`, exactly the TUI's `launch.rs` semantics),
  Acknowledge (`attention_acknowledge`). Each action names the capability
  it needs and is absent, not disabled, when the hello lacks it.

### D3 — Views

- `app.rs` — `Application`, one main window: the session list on the left,
  the selected session on the right (facts from `SessionPresentation`, the
  actions its state and capabilities allow, the embedded terminal).
- `terminal_element.rs` — the spike's Element: rows shaped as segments of
  consecutive narrow cells with style runs, each wide cell its own segment
  at `col × cell_width`; backgrounds and cursor as quads; 4 ms coalescing of
  notifies; the view wrapped `cached` so an idle terminal costs nothing per
  frame. Standalone mode: the same element in a window of its own, opened
  from the session view.
- `disclosure.rs` — the continuation disclosure, blocking until answered.

### D4 — Platform and verification envelope

macOS is the validated Desktop; the Metal toolchain is a build-time
requirement the dev-loop notes name. Linux: the crate compiles and its
non-rendering tests run in CI; the ubuntu runner installs
`libxkbcommon-dev libxkbcommon-x11-dev libwayland-dev libx11-xcb-dev
libfontconfig1-dev` as environment setup, not as verification logic. The
verification budget grows by gpui's compile; recorded as
`VERIFY_BUDGET_DEBT` if it crosses the map's threshold.

## Interfaces or persistence changed

No wire change, no durable state. `corral-client` gains two public
modules; `corral-tui` loses two private ones. `Cargo.toml` gains a member
and the gpui pin.

## Failure / unknown states

- Daemon unreachable: the list shows the last facts with their age and the
  activation error in the TUI's words; actions are absent; a terminal
  channel that ends shows *Detached* with the reason frame if one came.
- Snapshot prefix missing or stamped apart: not installed; resync.
- Replica poisoned: replica destroyed, *Terminal unavailable*, one resync;
  then stop; session and daemon truth untouched.
- Continuation refused: the refusal code shown; nothing launched.
- Unsupported or limited-awareness sessions: rendered as `PRODUCT.md` §6
  says, provably safe actions only.

## Tests

- `replica`: prefix order and stamps, desync on a missing `Geometry`,
  stale-epoch discard, palette checkpoint applied before the snapshot,
  poison → unavailable → one resync → stop, input encoding per mode, and a
  fidelity check against `corrald`'s own snapshot (the same comparison
  `snapshot_fidelity_tests` makes, from the client side).
- `bridge`: reconnection, ordered delivery across an epoch change, a
  channel that ends — against a real `corrald` on a socket pair, as
  `terminal_channel_tests` does.
- `sessions`/`actions`: decoding fixtures with unknown fields and
  discriminants; every action gated by capability; the disclosure shown
  before a resume.
- Views: `gpui` test-support (`TestAppContext`) for list and selection
  logic; no pixel assertions.
- `corral-tui`: its existing snapshot tests prove D1 changed nothing.

## Definition of done

- The core loop through the Desktop: see every session with its state,
  know what needs you (counts and rows), take control (open, type,
  interrupt, continue). Manually walked on macOS and recorded in the PR.
- The spike's frame harness rerun in **release profile** under a real
  display link on the Desktop's element: paint p95 within the 8 ms budget
  at 200×60, recorded (grill Q8/Q12).
- `./scripts/verify` on macOS and the Linux CI both green; the support
  matrix line for Linux Desktop reads *unvalidated*.
- ROADMAP §3's PR9 line points at this plan; the ledger's §8 row cites the
  release numbers.

## Decisions this plan asks the founder to accept

1. D1: the lift of session-row decoding and presentation into
   `corral-client`.
2. D2: no gpui-component in PR9; a plain binary, no bundle.
3. `sessions` polls at the TUI's cadence; no push channel in PR9.
4. The bounded resync policy: one automatic resync per failure episode.
5. One main window with an embedded terminal, standalone windows on demand.
6. Linux: compile and tests only; CI installs the dev libraries.

## Plan Size Justification

Over the target because PR9 is the largest single phase in the schedule
(`2026-08-22-surface-sequencing.md`) and this is its one plan: one crate,
one lift out of the TUI, and the client half of ADR 0017's contract. The
pieces share one owner boundary — the Desktop surface — and splitting them
would ship a Desktop that cannot yet render a terminal, or a replica with
no surface to prove it.
